# MetaLab — инструкции для Claude Code

## Что это за проект

MetaLab (ML) — независимая open-source платформа (Apache 2.0) для разработки
и выполнения бизнес-приложений, функциональный аналог «1С:Предприятия» на
собственном стеке (Go, BSL-движок, WebAssembly-клиент, PostgreSQL). Полное
видение и согласованные требования — [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md),
укрупнённый план по этапам — [docs/ROADMAP.md](docs/ROADMAP.md).

## Активный трекер итераций

Работа ведётся по **[docs/claude-iterations.md](docs/claude-iterations.md)** —
это рабочая версия плана с учётом разбора из
[docs/ITERATIONS-ANALYSIS.md](docs/ITERATIONS-ANALYSIS.md).

- [docs/ITERATIONS.md](docs/ITERATIONS.md) — исходный план **до** правок,
  оставлен как историческая версия. Не редактируется и не используется как
  источник правды для текущей работы.
- Перед началом работы всегда открывать `docs/claude-iterations.md`, чтобы
  увидеть текущую итерацию, её статус и точку продолжения (ссылка на
  `docs/ITERATION-NNN.md`, если для текущей итерации заведён отдельный файл
  детализации).

## Правило завершения итерации (обязательно, без исключений)

1. Реализован согласованный объём итерации.
2. Добавлены и успешно пройдены необходимые unit- и интеграционные тесты.
3. Выполнены статический анализ, `go test -race`, сборка затронутых ОС и
   применимые проверки производительности, гарантированного завершения и
   утечек ресурсов (горутины, соединения, файлы) — обязательно для кода с
   горутинами, сетью, транзакциями или файлами.
4. **Результат показан владельцу проекта и явно подтверждён им.** Это
   отдельный шаг после прохождения тестов и проверок, а не то же самое, что
   «тесты зелёные».
5. Только после пункта 4 — отдельный commit и push в GitHub.

Не переходить к шагу 5, пока владелец явно не подтвердил результат шага 4,
даже если все автоматические проверки пройдены.

## Правило дробления итераций

Если по ходу работы фактический объём итерации выходит за рамки одной
согласованной точки (прецедент — итерация 060, потребовавшая отдельного
`docs/ITERATION-060.md` и затронувшая 20+ файлов), итерация дробится на явные
подпункты прямо в `docs/claude-iterations.md`, а не расширяется молча одной
строкой. При необходимости заводится отдельный `docs/ITERATION-NNN.md` с
детализацией, как это уже сделано для 060.

## Модель/reasoning effort

В `docs/claude-iterations.md` итерации помечены тегами вида `⚙️ Sol / medium`
или `🧠 Astra / xhigh` — это соглашение из практики работы с Codex CLI и не
переносится на Claude буквально. Ориентир по смыслу тега:

- `Sol / medium` — ограниченная, хорошо определённая задача — обычный режим.
- `Sol / high` / `Sol / xhigh` — крупная прикладная подсистема или сложная
  локализованная логика — стоит закладывать больше времени на проверку
  граничных случаев.
- `Astra / high` / `Astra / xhigh` — новая архитектура, безопасность,
  конкурентность, целостность данных — использовать более высокий reasoning
  effort и явно предупреждать пользователя, если задача требует переключения
  на более тщательный разбор, прежде чем начинать реализацию.
