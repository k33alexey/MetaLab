# MetaLab — согласованные верхнеуровневые требования

Статус: согласовано для дальнейшей детализации  
Версия: 1.0  
Дата: 2026-09-01

## 1. Видение

MetaLab (сокращённо **ML**) — независимая open-source платформа для разработки и выполнения бизнес-приложений. Платформа функционально близка к «1С:Предприятию», но имеет собственную реализацию на Go, современный веб-интерфейс и открытый файловый формат проектов.

ML не зависит от установленной 1С, её закрытого кода, компонентов или форматов исполнения. Проект распространяется по лицензии **Apache License 2.0**.

Ключевые цели:

- знакомая BSL-разработчикам модель разработки;
- высокая скорость создания прикладных решений;
- быстрый и отзывчивый интерфейс;
- надёжные транзакции и сохранность данных;
- открытые исходники, форматы и инструменты;
- перенос существующих XML-конфигураций 1С в ML.

## 2. Терминология

- **ML Manager** — настольный интерфейс управления службой и базами.
- **ML Service** — постоянно работающая системная служба, обслуживающая запущенные базы.
- **ML Studio** — собственная IDE платформы, запускаемая из ML Manager в окне WebView.
- **ML Project** — файловый проект прикладного решения, аналог конфигурации 1С.
- **ML App** — пользовательское веб-приложение, сформированное из ML Project.
- **ML Portal** — единая точка входа со списком доступных баз.
- **ML Agent** — отдельный необязательный компонент для локального оборудования.
- **База** — отдельная база PostgreSQL с опубликованным ML Project и прикладными данными.

## 3. Общая архитектура

```text
ML Manager ──управляет──> ML Service ──> PostgreSQL
                               │
                               ├──> ML Studio (WebView)
                               ├──> ML Portal / ML App (браузер)
                               └──> ML Agent ──> оборудование
```

- Основная поставка содержит один бинарник `ml` (`ml.exe`), работающий как ML Manager или ML Service.
- ML Studio и ML App используют веб-технологии, но отдельными бинарниками не являются.
- ML Studio локально открывается в системном WebView, без Electron.
- ML App работает только в браузере и требует соединения с ML Service.
- Закрытие ML Manager не останавливает ML Service и запущенные базы.
- ML Agent поставляется отдельно только для рабочих мест с оборудованием.
- ML Service поддерживает Linux, Windows и macOS.
- ML Manager и ML Studio первоначально поддерживают Windows и macOS.
- На Linux администрирование выполняется через ML Portal и CLI.
- Первая стабильная версия работает на одном надёжном ML Service. Кластер не обязателен, но его будущее добавление не должно требовать изменения ML Project.

## 4. Управление базами

ML Manager предоставляет список баз и действия:

- добавить, настроить, запустить и остановить базу;
- запретить новые подключения или перевести базу в обслуживание;
- просмотреть, уведомить и завершить активные сеансы;
- открыть ML Studio;
- создать резервную копию и восстановить базу;
- создать отладочную базу на основе основной.

База имеет один из режимов:

- **Основная** — рабочая эксплуатация; отладка отключена, публикация и миграции выполняются явно;
- **Отладка** — разработка и тестирование; разрешены отладка и ускоренная публикация.

При регистрации ML проверяет фактическую PostgreSQL-базу. Одну физическую БД нельзя зарегистрировать повторно или одновременно использовать как основную и отладочную. Разные базы могут находиться на одном сервере PostgreSQL.

При создании базы «Отладка» администратор задаёт отдельное целевое подключение, а затем выбирает:

- скопировать основную базу без её остановки;
- создать чистую базу с метаданными, системными и предопределёнными данными.

В отладочной копии регламентные задания, внешние интеграции и оборудование выключаются. Регламентное задание можно выполнить вручную только после подтверждения.

## 5. PostgreSQL и хранение данных

- PostgreSQL — единственная поддерживаемая СУБД.
- Файлового режима информационной базы нет.
- PostgreSQL устанавливается и обслуживается отдельно от ML.
- ML Manager проверяет совместимость PostgreSQL и соединение.
- При наличии административных прав ML Manager умеет создать базу и отдельного технического пользователя с минимальными правами.
- Прикладные данные разных баз физически изолированы.
- Небольшая служебная база **ML System** хранит пользователей платформы, список баз и настройки ML Service.
- Двоичные данные и присоединённые файлы хранятся в PostgreSQL; внешних файловых или S3-хранилищ нет.

Пароли подключений и секреты не хранятся в YAML. Они сохраняются защищённо средствами ОС и платформы.

## 6. ML Project и Git

ML Project является обычным каталогом в файловой системе и основным источником метаданных и кода.

```text
MyProject/
├── mlproject.yaml
├── metadata/
├── modules/*.bsl
├── forms/*.yaml
├── reports/
├── tests/
└── assets/
```

- YAML — основной формат метаданных и форм.
- BSL-код хранится в отдельных текстовых файлах.
- Ресурсы хранятся отдельными файлами, без Base64 в YAML.
- Объекты имеют стабильные UUID, а сериализация YAML — стабильный порядок полей.
- Git заменяет хранилище конфигурации 1С.
- Git-интеграция ML Studio включает clone, status, diff, commit, pull, push, ветки и показ конфликтов.
- ML Studio визуально редактирует дерево, свойства и формы, изменяя файлы проекта под капотом.
- Отдельная резервная копия ML Project не создаётся: исходники и история находятся в Git.
- В основную базу публикуется только Git commit. В отладочную допустима публикация незакоммиченных изменений.

Для конкретной базы ML Studio работает монопольно: одновременно метаданные редактирует один человек. Другим показываются владелец и время сеанса. Администратор платформы может принудительно завершить зависший сеанс. Совместная разработка ведётся через Git и отдельные отладочные базы.

## 7. Публикация и миграции

Сохранение файла не изменяет работающую базу. Изменения становятся доступны после команды **«Опубликовать»**.

Публикация включает:

1. проверку синтаксиса, метаданных и разрешений;
2. сборку BSL в байткод;
3. сравнение схемы и построение плана миграции;
4. показ добавляемых, изменяемых и удаляемых структур;
5. подтверждение администратора метаданных;
6. миграцию PostgreSQL;
7. атомарную активацию новой версии.

- Безопасные изменения кода и форм применяются без остановки базы.
- Текущие транзакции завершаются на прежней версии; новые операции используют новую.
- Изменённая открытая форма предлагает обновиться без повторного входа.
- При несохранённых данных F5, закрытие или обновление формы вызывает предупреждение; дополнительно поддерживаются черновики.
- Удаление реквизита после подтверждённой публикации физически удаляет колонку PostgreSQL. ML явно предупреждает о потере данных.
- Версию PostgreSQL и резервные копии контролирует администратор.
- ML Project и база хранят UUID проекта, Git commit и версию схемы.
- Публикация устаревшего или разошедшегося проекта блокируется. Для отката основной базы используется согласованная пара Git-версии и резервной копии PostgreSQL.

Системное право **«Администратор метаданных»** разрешает доступ к ML Studio, публикацию проекта и миграции. Право **«Администратор платформы»** разрешает управлять базами, службой и сеансами.

## 8. BSL и исполняющая среда

- Синтаксис BSL и его русские/английские варианты максимально совместимы с 1С.
- Собственные ключевые слова, глобальные функции и пространство имён ML пока не вводятся.
- Целевая совместимость включает всю стандартную библиотеку BSL и контролируется автоматической матрицей.
- Поддерживаются `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста` и совместимое разделение контекстов.
- При публикации BSL компилируется в байткод.
- Серверный байткод выполняется виртуальной машиной на Go.
- Клиентский BSL выполняется в браузере через WebAssembly; решение подтверждается прототипом по скорости и размеру.
- Ошибки содержат описание, стек вызовов и ссылку на исходную строку.
- Порядок событий объектов, форм и подписок совместим с 1С и закрепляется тестами.
- Исключение в обработчике отменяет связанную транзакционную операцию.
- Старые ML Project продолжают работать после совместимых обновлений платформы без изменения исходников.

BSL выполняется в песочнице. ML Project объявляет, а администратор подтверждает права на файловые каталоги, исходящие сетевые адреса, оборудование и другие опасные операции. Произвольный запуск процессов ОС запрещён по умолчанию.

- DDD используется во внутренней архитектуре ML, но не навязывается ML Project.

## 10. Прикладная модель данных

- Все ссылочные объекты имеют неизменяемый внутренний UUID.
- Сохраняются ссылки, коды и номера, автонумерация, предопределённые элементы, пометка удаления и проверка ссылочной целостности.
- Окончательное удаление выполняется только после проверки ссылок, а его факт записывается в журнал.
- Механизм проведения документов сохраняется полностью.
- Документ и его движения записываются в одной транзакции.
- Поддерживаются проведение, отмена проведения, наборы движений и `ОбработкаПроведения`.
- Для документа-регистратора ML App автоматически показывает команду **«Движения документа»**.
- Транзакции, автоматические и управляемые блокировки выполняются на ML Server независимо от браузера.
- Поддерживаются начало, фиксация, откат, контроль взаимоблокировок и оптимистическая проверка изменения.
- Транзакция не должна ожидать действий пользователя в форме.

## 11. Язык запросов

- Язык запросов ML максимально совместим с языком запросов 1С.
- Запросы работают с логическими именами метаданных, а не с физической схемой PostgreSQL.
- Поддерживаются параметры, соединения, группировки, агрегаты, сортировка и временные таблицы.
- Виртуальные таблицы включают `СрезПервых`, `СрезПоследних`, `Остатки`, `Обороты`, `ОстаткиИОбороты` и позднее таблицы бухгалтерских/расчётных регистров.
- ML транслирует запросы в оптимизированный SQL PostgreSQL.
- Доступны план выполнения и диагностика медленных запросов.

## 12. ML Studio

ML Studio включает:

- визуальное дерево метаданных и редактор свойств;
- редактор BSL с подсветкой, автодополнением и проверкой синтаксиса;
- переход к определению, поиск использований и безопасное переименование;
- поиск по дереву, BSL, формам и макетам;
- локальный синтаксис-помощник с поиском и F1;
- документацию процедур и функций ML Project;
- визуальный конструктор управляемых форм;
- конструктор запросов и Компоновку данных ML;
- Git-интеграцию;
- отладчик и панель тестов;
- управление публикацией и миграциями;
- просмотр ошибок и журналов.

Конструктор форм поддерживает дерево групп и элементов, drag-and-drop, панель свойств, привязки, адаптивный предпросмотр и быстрое создание BSL-обработчика.

Отладчик включает точки останова, пошаговое выполнение, стек, переменные, табло, вычисление выражений, остановку по исключениям и отладку клиентского/серверного BSL, пользовательских сеансов и заданий.

## 13. Автоматические тесты

В дереве ML Studio существует ветка **«Тесты»** с тестовыми BSL-модулями.

- Экспортная процедура тестового модуля является отдельным тестом.
- Тест запускается из строки, модуля, всей ветки или командой `ml test`.
- Результаты показываются со стеком и переходом к строке.
- Поддерживаются CI и отчёт о покрытии.
- Тесты выполняются только в базе «Отладка».
- Обычный тест выполняется в отдельной транзакции, которая принудительно откатывается.
- Тест видит метаданные и может создавать объекты и движения, но данные после него не остаются.
- Тест можно выполнять под выбранной ролью.
- Внешние вызовы и оборудование заменяются имитациями.
- Тестовые модули не публикуются в основную базу.

## 14. ML App и управляемые формы

- Поддерживаются только управляемые формы.
- Без собственной формы ML автоматически строит формы объекта, списка и выбора.
- Формы используют современные адаптивные веб-компоненты, а не копируют внешний вид 1С.
- Импортированная форма сохраняет структуру, элементы, команды и обработчики, но отображается компонентами ML.
- Интерфейс адаптируется к компьютерам, планшетам и телефонам.
- Поддерживаются сенсорное управление, предпросмотр экранов и доступ к камере через браузер.
- ML App можно установить как PWA-ярлык, но offline-режима нет.
- Поддерживаются две последние основные версии Chrome, Edge, Firefox, Safari и Opera. Internet Explorer исключён.

Динамические списки используют серверные отборы и сортировку, виртуальную прокрутку и страницы по 20, 50 или 100 строк. Для больших изменяемых списков используется курсорная пагинация.

## 15. Поиск

ML Studio ищет объекты в дереве, текст в BSL/формах/макетах, ссылки и места использования.

Глобальный поиск ML App ищет только доступные объекты и команды по полным и неполным словам. Он не исправляет опечатки и не ищет по пользовательским данным.

Локальный поиск списка работает по отмеченным разработчиком полям. Для них ML создаёт PostgreSQL-индексы. Поиск учитывает права и политики доступа.

## 16. Компоновка и печать

**Компоновка данных ML** сохраняет знакомую модель СКД: наборы данных, связи, параметры, вычисляемые поля, отборы, группировки, ресурсы, варианты настроек, оформление, расшифровки и визуальный конструктор. Поддерживается импорт схем из XML 1С.

Табличный документ поддерживает области макета, программный вывод из BSL, печать и экспорт в PDF/XLSX.

## 17. Пользователи и доступ

- Используются внутренние учётные записи ML.
- LDAP, Active Directory, OpenID Connect и двухфакторная авторизация исключены.
- При первом запуске администратор задаёт пароль; стандартного пароля нет.
- Создаются одноразовые коды восстановления; аварийный сброс доступен локальному администратору ОС через CLI.
- Пользователь один раз входит в ML Portal и видит разрешённые базы.
- Если база одна, обычный пользователь сразу переходит в ML App.
- После выбора базы пользователь открывает ML App, а администратор метаданных может выбрать ML App или ML Studio.
- Повторный ввод пароля не требуется.

Доступ включает системные права, роли ML Project, права на операции и декларативные политики строкового доступа вместо ручных шаблонов RLS. Политики автоматически применяются к формам, запросам, отчётам, заданиям и HTTP-сервисам. Скрытие элемента формы не является защитой.

## 18. Языки

- ML Manager, ML Studio и ML App изначально доступны на `uk`, `ru`, `en`.
- ML Project может добавлять языки.
- Язык имеет идентификатор, наименование и стандартный код локали.
- Переводимые свойства редактируются единым диалогом для всех языков.
- Язык применяется к интерфейсу, форматированию и печатным формам.
- Подстановка: язык пользователя, основной язык проекта, первый заполненный перевод.
- Язык ML Manager задаётся параметром запуска и сохраняется.

## 19. Присоединённые файлы

ML предоставляет встроенный механизм без объектов БСП:

- разработчик включает свойство **«Присоединённые файлы»** у справочника или документа;
- ML автоматически добавляет команду и готовую форму;
- хранятся содержимое, имя, размер, тип, хеш, автор, дата и владелец;
- права наследуются от объекта-владельца;
- версии файлов включаются отдельной настройкой;
- данные хранятся в PostgreSQL.

При импорте ML обнаруживает подсистему файлов БСП и предлагает заменить её встроенным механизмом, не импортируя лишние служебные объекты.

## 20. История изменений

- История отдельно включается для выбранных справочников и документов.
- Сохраняются старые и новые значения изменённых реквизитов, автор и время.
- Команда истории видна только разрешённым ролям.
- Доступно представление «До / После».
- Восстановление требует отдельного права, выполняется транзакционно и создаёт новую запись истории.
- Администратор задаёт период полного хранения и минимальное количество версий после него.
- Очистка выполняется регламентным заданием.
- При окончательном удалении объекта история удаляется, а факт удаления остаётся в журнале.

## 21. Задания и уведомления

- Поддерживаются фоновые и регламентные задания.
- Настраиваются число повторов, интервал, максимальное время и параллельность.
- Журнал хранит попытки, прогресс, длительность, результат, ошибку и стек.
- Ошибки выделяются красным.
- ML Manager и ML Portal имеют центр административных уведомлений с группировкой повторов.
- Внешние email/webhook-уведомления не обязательны.
- В отладочной базе регламентные задания выключены и запускаются вручную с подтверждением; фоновые задания доступны.

## 22. Интеграции и оборудование

- Основной способ интеграции — явно созданные HTTP-сервисы на BSL и JSON.
- Автоматический CRUD REST/OData API отсутствует.
- SOAP и XDTO отсутствуют.
- Для HTTP-сервисов используются сервисные учётные записи и Bearer-токены.
- Токены имеют права, срок действия, отзыв, хранятся как хеш и журналируются.

ML Agent обеспечивает принтеры, сканеры, камеры, кассы, весы, терминалы и другое торговое оборудование. API драйверов открыт. Драйверы изолированы, декларируют разрешения и не имеют прямого доступа к PostgreSQL.

## 23. Настройки и секреты

- Метаданные **«Хранилища настроек»** поддерживают пользовательские настройки форм, отчётов и приложения.
- Отдельное защищённое хранилище секретов находится на уровне базы в ML Manager.
- Секреты не попадают в YAML, Git, журналы или ошибки.
- BSL получает секрет по имени и только при наличии разрешения.
- Точный BSL-интерфейс определяется при детализации безопасности.

## 24. Журналы и эксплуатация

Обязательны журнал регистрации, технический журнал ML Server и журнал заданий. Они поддерживают отборы, уровни событий, структурированный формат и переходы к объектам. Техническая диагностика включает запросы, блокировки, ошибки, длительность и ресурсы. Секреты маскируются.

ML Server поддерживает встроенный HTTPS и работу за reverse proxy. Телеметрия выключена по умолчанию; администратор может добровольно включить обезличенную диагностику или выгрузить локальный пакет.

## 25. Резервное копирование

- ML Manager создаёт стандартные локальные резервные копии PostgreSQL без остановки основной базы.
- Администратор задаёт каталог, расписание и срок хранения.
- Перенос копий наружу выполняется сторонними средствами.
- Восстановление доступно через ML Manager.
- Копия включает прикладные данные, опубликованные метаданные и файлы.
- ML Project восстанавливается из Git по commit, записанному в базе.

## 26. Обновление платформы

- Исходники, документация и тесты публикуются в GitHub.
- GitHub Actions собирает подписанные установщики Windows/macOS и серверные сборки Linux.
- ML Manager проверяет подписанный файл версий по HTTPS и сообщает о выпуске.
- Проверку можно отключить; установка выполняется только после подтверждения.
- Перед обновлением проверяется совместимость баз.
- Совместимое обновление не требует изменения ML Project.
- Сведения о базах и проектах не отправляются.

## 27. Импорт из 1С

- Поддерживается односторонний импорт каталога XML-выгрузки конфигурации 1С.
- Импорт создаёт новый ML Project, но не публикует его автоматически.
- Переносятся поддерживаемые метаданные, BSL, управляемые формы и схемы компоновки.
- Неподдерживаемые объекты пропускаются с отчётом.
- Разработчик проверяет дерево и затем публикует проект и миграцию PostgreSQL.
- Повторная синхронизация, обратный экспорт, импорт `.cf` и перенос пользовательских данных отсутствуют.
- Обычные формы, XDTO/SOAP и функциональные опции пропускаются.

## 28. Производительность и надёжность

Целевой профиль первой стабильной версии:

- один ML Service;
- не менее 1 000 одновременных пользователей;
- база до 30 ГБ;
- типовые операции — не более 300 мс при штатной нагрузке;
- открытие типовой формы в локальной сети — не более 1 секунды на 95-м процентиле; это предел, а не среднее.

Сложные отчёты получают отдельные бюджеты. Для релиза публикуется воспроизводимый профиль оборудования и нагрузки.

Обязательны сохранность подтверждённых транзакций, изоляция сбоев сеансов, ограничения BSL по времени/памяти, профилирование и тесты гонок, конкурентности, миграций, нагрузки, длительной работы и аварий. Регресс производительности блокирует стабильный выпуск.

Отказоустойчивость PostgreSQL, реплики и внешнее хранение резервных копий определяет системный администратор. ML предоставляет совместимость, проверки и инструкции, но не заменяет PostgreSQL.

## 29. Демо-проект

В репозитории и поставке присутствует демонстрационный ML Project «Продажи и склад»: товары, контрагенты, поступления, продажи, остатки, формы, роли, отчёт, файлы и тесты. Он служит примером, интеграционным тестом и сценарием показа платформы.
