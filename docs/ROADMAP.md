# MetaLab — согласованный укрупнённый roadmap

Статус: согласовано для дальнейшей детализации  
Версия: 1.0  
Дата: 2026-09-01

Roadmap основан на [REQUIREMENTS.md](./REQUIREMENTS.md). Здесь зафиксированы порядок и результаты крупных этапов без оценки сроков и детализации задач.

## Правила разработки

- Каждый этап заканчивается работающим проверяемым результатом.
- Возможность не считается готовой без автоматических тестов и документации.
- Производительность измеряется с первого прототипа, а не после завершения функционала.
- Ошибки сохранности данных, обход прав и критические регрессии скорости блокируют переход дальше.
- Вначале реализуется минимальный сквозной сценарий, затем расширяется совместимость с 1С.
- Форматы проекта, байткода, публикации и БД версионируются с самого начала.

## Этап 0. Спецификации и проверка архитектурных рисков

### Работы

- Создать репозиторий, лицензию Apache 2.0, правила вклада и CI.
- Зафиксировать терминологию, границы компонентов и формат архитектурных решений.
- Подготовить спецификацию минимального синтаксиса BSL и матрицу совместимости.
- Спроектировать стабильные UUID и черновой формат YAML для ML Project.
- Создать прототипы:
  - парсер BSL;
  - компиляция в байткод и VM на Go;
  - выполнение клиентского байткода через WebAssembly;
  - WebView для ML Studio;
  - преобразование метаданных в схему PostgreSQL;
  - базовый запрос к PostgreSQL через логическое имя метаданных.
- Измерить скорость, память и размер клиентской загрузки.

### Результат

Главные технические решения подтверждены кодом и бенчмарками. Риски, способные сделать платформу медленной или слишком тяжёлой, сняты до основной разработки.

## Этап 1. Каркас платформы и управление базами

### Работы

- Реализовать основной бинарник ML в режимах Manager и Service.
- Реализовать системную службу Windows/macOS/Linux и корректное завершение.
- Создать ML System в PostgreSQL.
- Добавить первый запуск, администратора платформы и восстановление доступа.
- Реализовать реестр баз, проверку уникальности PostgreSQL-базы и состояния запуска.
- Добавить создание технического пользователя и базы PostgreSQL.
- Реализовать режимы «Основная» и «Отладка».
- Добавить запуск, остановку, обслуживание, запрет входа и базовый просмотр сеансов.
- Создать минимальный ML Portal и общий вход.
- Настроить структурированные логи и проверки состояния.
- Организовать сборки Windows/macOS/Linux через GitHub Actions.

### Результат

ML устанавливается, создаёт системную среду, подключает PostgreSQL, регистрирует и запускает несколько изолированных баз. Закрытие Manager не останавливает Service.

## Этап 2. ML Project, Git, публикация и миграции

### Работы

- Утвердить файловую структуру ML Project и схемы YAML.
- Реализовать чтение, валидацию и стабильную сериализацию проекта.
- Создать базовый интерфейс ML Studio: дерево, свойства, файловый редактор.
- Добавить монопольный сеанс Studio для базы.
- Реализовать базовую Git-интеграцию.
- Связать проект, Git commit, опубликованную версию и схему БД.
- Реализовать сборку пакета публикации.
- Построить план миграции PostgreSQL для таблиц, колонок, типов, индексов и ограничений.
- Добавить явное подтверждение опасных миграций.
- Блокировать публикацию устаревшей или разошедшейся Git-версии.
- Реализовать локальные резервные копии и восстановление PostgreSQL.
- Добавить создание чистой отладочной базы и согласованной копии основной без остановки.

### Результат

Разработчик клонирует каталог из Git, открывает его в ML Studio и безопасно публикует версионированные метаданные в отдельную PostgreSQL-базу.

## Этап 3. BSL, данные и первый сквозной сценарий

### Работы

- Реализовать основной синтаксис BSL на русском и английском языках.
- Реализовать модули, процедуры, функции, исключения, коллекции и базовые типы.
- Добавить директивы клиентского/серверного выполнения.
- Стабилизировать байткод, Go VM и клиентскую WebAssembly VM.
- Реализовать базовые метаданные:
  - константы;
  - перечисления;
  - справочники;
  - документы;
  - регистры сведений;
  - регистры накопления;
  - общие модули и подписки на события.
- Реализовать ссылки UUID, нумерацию, предопределённые данные и пометку удаления.
- Реализовать транзакции, блокировки и ссылочную целостность.
- Реализовать проведение документов и движения регистров.
- Создать базовый язык запросов и первые виртуальные таблицы.
- Автоматически строить формы объекта, списка и выбора.
- Реализовать динамические списки и пагинацию.
- Начать демо-проект «Продажи и склад».

### Результат

В ML можно создать, опубликовать и запустить небольшое приложение с товарами, контрагентами, поступлением, продажей и остатками.

## Этап 4. Полноценная ML Studio

### Работы

- Реализовать редактор BSL с подсветкой, автодополнением и синтаксической проверкой.
- Добавить навигацию, поиск использований и переименование.
- Реализовать локальный синтаксис-помощник и F1.
- Создать визуальный конструктор управляемых форм с drag-and-drop.
- Добавить адаптивный предпросмотр.
- Реализовать конструктор запросов.
- Создать отладчик:
  - точки останова;
  - пошаговое выполнение;
  - стек и переменные;
  - табло и вычисление выражений;
  - клиентские/серверные сеансы и задания.
- Добавить ветку тестов, транзакционный runner, панель результатов, CLI и покрытие.
- Доработать diff и разрешение конфликтов Git.

### Результат

Прикладной разработчик выполняет основной цикл — код, форма, отладка, тест, commit и публикация — не выходя из ML Studio.

## Этап 5. ML App, безопасность и мультиязычность

### Работы

- Создать современную адаптивную систему управляемых форм.
- Поддержать компьютеры, планшеты, телефоны и PWA-установку без offline.
- Реализовать предупреждения о несохранённых данных и черновики форм.
- Добавить безопасное обновление открытых сеансов после публикации.
- Реализовать ML Portal, список баз и единый вход без повторного пароля.
- Добавить роли, объектные права и декларативные политики доступа к строкам.
- Реализовать песочницу BSL и подтверждение разрешений проекта.
- Создать защищённое хранилище секретов.
- Реализовать `uk`, `ru`, `en` и механизм языков ML Project.
- Добавить глобальный поиск по объектам/командам и локальный индексируемый поиск списков.
- Реализовать администрирование активных сеансов и сообщения пользователям.
- Добавить HTTPS и работу за reverse proxy.

### Результат

Многопользовательское приложение безопасно работает в поддерживаемых браузерах и адаптируется к разным экранам.

## Этап 6. Бизнес-механизмы платформы

### Работы

- Расширить обязательное дерево метаданных:
  - журналы документов;
  - отчёты и обработки;
  - планы видов характеристик;
  - планы счетов;
  - регистры бухгалтерии;
  - роли, параметры сеанса, общие реквизиты и определяемые типы;
  - общие команды, формы, макеты, картинки, стили и хранилища настроек.
- Расширить стандартную библиотеку BSL и матрицу совместимости.
- Завершить виртуальные таблицы регистров.
- Реализовать Компоновку данных ML и визуальный конструктор.
- Реализовать табличный документ, печать, PDF и XLSX.
- Добавить автоматическую команду «Движения документа».
- Реализовать встроенные присоединённые файлы и их версии.
- Реализовать историю изменений объектов и восстановление по праву.
- Реализовать фоновые/регламентные задания, повторы и ручной запуск в отладочной базе.
- Создать журнал регистрации, технический журнал и журнал заданий.
- Добавить центр административных уведомлений.

### Результат

ML покрывает основные механизмы разработки и эксплуатации полноценных учётных приложений.

### Работы

- Реализовать HTTP-сервисы на BSL и JSON.
- Добавить сервисные учётные записи и Bearer-токены.
- Реализовать аудит и ограничения исходящих соединений.
- Создать ML Agent и защищённый протокол с ML Service.
- Опубликовать открытый API драйверов.
- Реализовать первые драйверы для сканера, печати и камеры.
- Подготовить основу для касс, весов, терминалов и принтеров этикеток.

### Результат

ML безопасно интегрируется с внешними системами и локальным торговым оборудованием без прямого доступа драйверов к БД.

## Этап 8. Импорт XML-конфигураций 1С

### Работы

- Разобрать формат каталога XML-выгрузки.
- Импортировать поддерживаемое дерево, BSL, управляемые формы и СКД.
- Создавать ML Project без автоматической публикации.
- Формировать подробный отчёт о перенесённых, преобразованных и пропущенных объектах.
- Обнаруживать подсистему присоединённых файлов БСП и предлагать замену механизмом ML.
- Подготовить набор реальных тестовых конфигураций с разрешённым использованием.
- Проверить импорт повторяемыми тестами совместимости.

### Результат

Разработчик переносит XML-конфигурацию 1С в новый ML Project, проверяет её в Studio и самостоятельно публикует в PostgreSQL.

## Этап 9. Производительность и стабильный выпуск

### Работы

- Закрыть обязательную матрицу BSL и метаданных для версии 1.0.
- Провести нагрузочные испытания на 1 000 одновременных пользователей и базе 30 ГБ.
- Подтвердить пределы 300 мс для типовых операций и 1 секунду для формы на 95-м процентиле.
- Провести длительные прогоны, race-тесты, fault injection и аварийное завершение процессов.
- Проверить транзакции, блокировки, восстановление копий и миграции.
- Провести аудит безопасности и разрешений BSL.
- Оптимизировать запуск, память, размер ML Studio и WebAssembly-клиента.
- Завершить документацию установки, разработки, администрирования и восстановления.
- Довести демо-проект до законченного демонстрационного состояния.
- Подготовить подписанные установщики и механизм уведомлений об обновлениях.

### Результат

Выпущена ML 1.0: документированная, измеренная и пригодная к промышленной эксплуатации односерверная платформа.

## Последующие этапы

После ML 1.0 отдельно рассматриваются:

- планы обмена;
- планы видов расчёта и регистры расчёта;
- бизнес-процессы и задачи;
- внешние источники данных;
- кластер ML Service;
- расширенные драйверы оборудования;
- импорт данных и, при необходимости, `.cf`;
- дополнительные способы корпоративной авторизации;
- внешние хранилища больших файлов.

Не планируются без отдельного пересмотра требований: файловая база, SOAP/XDTO, автоматический REST/OData, обычные формы, расширения ML Project, обратный экспорт в 1С и offline-режим ML App.
